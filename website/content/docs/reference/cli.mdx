Run `node dist/cli/main.js --help` for the current command syntax. The installed binary name is `clearings`.

| Command | Purpose | Main inputs |
| --- | --- | --- |
| `inventory` | Account for tracked Git entries | Repository, ref or target manifest, scope |
| `scan` | Extract bounded TypeScript structure | Inventory options; optional project, strict mode |
| `benchmark-fetch` | Fetch and verify a pinned bare repository | Target manifest; new output directory |
| `propose` | Export exact evidence and author instructions | Scan, repository, instruction, version, byte budget |
| `import` | Validate a supplied interpretation | Response, request, scan, repository |
| `replay` | Import with a recorded-replay label | Same inputs as import |
| `validate` | Check artifact integrity and optional source | Artifact; scan/request/repository as required |
| `inspect` | List or select v0.2 records | Model; capability, behavior, or ID |
| `context` | Export bounded v0.2 context | Model, selection, byte budget |
| `evidence` | Retrieve exact source text | Scan, repository, evidence ID |
| `explain` | Render a capability report | Model, scan, repository, capability, optional plan/audience/format |

## Common options

`--out` saves a new file. It never overwrites an existing file and rejects target paths. `inspect` and `context` require `--repository` when saving. Their source recheck additionally requires `--scan`.

JSON goes to stdout; report output is HTML or Markdown. Progress and errors go to stderr. Source selections use literal paths. Options not supported by a command are rejected.

`propose --schema-version 0.2.0` selects contracts. Its default is `0.1.0`. Historical `inspect` and `context` accept v0.2 models. Historical `explain` accepts both model versions and requires the matching presentation version.

Typed v0.3 specifications use `--operation <id-or-alias>` with `inspect`, `context`, and `explain`. Selected output supports JSON, Markdown, or HTML. `check <specification.json> --operation <alias> --observation <file>` returns JSON: exit 0 for pass, 1 for failed rules, and 3 for unknown. Invalid inputs use exit 2. These commands do not revalidate Git source; `--scan` is rejected. See [typed specifications](/docs/guides/specifications).

Legacy `context --format readable-json` expands assertion prose in place. It remains explicitly unformalized.

`context --no-neighbors` omits optional neighboring behaviors. `--max-bytes` measures compact UTF-8 JSON including the newline. `inspect` and `context` support JSON output only.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Success, including a reported partial artifact |
| 1 | Operational failure |
| 2 | Invalid input or schema |
| 3 | Strict scan reports errors or unresolved facts |

Read artifact status, diagnostics, and coverage even when the exit code is zero.
