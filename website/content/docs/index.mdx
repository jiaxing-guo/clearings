Clearings builds an **internal representation for AI coding**. It gives people and coding agents a shared set of records for functions, behavior, state, and source evidence.

Suppose you need to know: *If a handler returns no response, what happens next?* A call list is not enough. You also need the branch conditions, the shared state, and the failure boundary.

Clearings keeps those rules in semantic contracts. You can read a report, inspect the records, or export a selection for your agent.

## Try the recorded example

The repository includes a Hono example. You can inspect it without an API key or a Hono checkout.

```bash
npm ci --ignore-scripts
npm run build
node dist/cli/main.js inspect benchmarks/results/hono-contracts/semantic.json --behavior response-selection
```

The JSON identifies the selected behavior and its linked functions, assertions, state, and unknowns. `source_rechecked` is `false`: this command checks the artifact's integrity but does not open the Hono repository.

[Follow the quickstart](/docs/quickstart) to export context and reproduce the reports.

## Know the current boundary

This is a private review prototype. The recorded example covers Hono request dispatch and middleware composition. It does not cover all of Hono or your application handlers.

Source extraction is automatic and bounded. Semantic interpretation arrives through explicit file exchange with an agent or person. Clearings has no built-in model endpoint. A valid source citation does not prove an English claim. Independent claim-support review is pending.
