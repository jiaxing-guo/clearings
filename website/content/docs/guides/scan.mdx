---
title: "Scan a repository"
description: "Extract structure and exact evidence from a Git commit."
---

A scan reads committed Git objects. It does not change the target checkout, run target scripts, or install target dependencies. Dirty working-tree edits are outside the snapshot.

## Select source

```bash
node dist/cli/main.js scan /path/to/repository --ref HEAD --include src --out /tmp/clearings-scan.json
node dist/cli/main.js validate /tmp/clearings-scan.json --repository /path/to/repository
```

Use a new output path outside the target. `--include` and `--exclude` are literal repository-relative paths; they are not glob expressions. Repeat them to select more paths.

## Check the result

Read `coverage` and `diagnostics` before using the records. Selected files can fail to parse. Calls through callbacks or dynamic dispatch can remain unresolved even when parsing succeeds.

Supporting source can resolve references outside the selected scope. It is labeled separately; Clearings does not extract all of its function bodies. Exclusions and symlinks are not followed.

## Select a project configuration

```bash
node dist/cli/main.js scan /path/to/repository --include src --project tsconfig.build.json
```

The adapter discovers ancestor configurations, references, inherited settings, and repository imports. An explicit project file must be a tracked JSON file. Custom JSON names are supported. Missing external types remain unavailable; a source-only scan is not a full target typecheck.

## Require a strict result

Add `--strict` to return exit code 3 for a partial scan or unresolved facts. The artifact still reports its coverage. A non-strict partial scan returns exit code 0, so inspect the status rather than assuming success means complete analysis.
