---
title: "Inspect and export context"
description: "Give an agent the required rules for one question."
---

Start with a capability or behavior alias. Use canonical IDs when you need one exact record.

## Follow direct links

```bash
node dist/cli/main.js inspect semantic.json --behavior response-selection
node dist/cli/main.js inspect semantic.json --id '<function-id>'
```

An inspection returns records, direct references, unknowns, and evidence metadata. Use another inspection to expand a referenced contract. JSON-only inspection checks internal integrity. Supply both `--scan` and `--repository` to recheck immutable source.

## Keep required context

```bash
node dist/cli/main.js context semantic.json --behavior response-selection --max-bytes 131072 --no-neighbors
```

Selection follows function dependencies, state, assertions, flows, implementation anchors, and relevant critical unknowns. Referenced flows remain complete, including branches and failure steps. This can be larger than the specific function you selected.

The byte budget applies to compact JSON plus its final newline. Use `serializeContextPack` in library code. Pretty-printing changes its size.

## Understand omissions

Optional neighboring behaviors can be included when the budget permits. `--no-neighbors` retains only the required selection. The output lists omitted record IDs and evidence IDs, plus retrieval instructions.

If required records exceed the budget, `CONTEXT_BUDGET` reports the required size. Select a narrower behavior or increase the budget. The maximum is 2,097,152 bytes. Clearings does not drop a consequential branch to meet the limit.

## Read exact evidence

```bash
node dist/cli/main.js evidence scan.json --repository repo --id '<evidence-id>'
```

Context packs carry source references rather than excerpt text. Evidence lookup checks the pinned source before returning the excerpt. Deferred evidence IDs require the original scan; they are not necessarily present in the semantic request.

For an agent task, retain its input, extra evidence requests, final answers, unknowns, and available usage. Keep expected answers outside its input. A useful demonstration does not establish a general efficiency benefit.
